## 0. 理念(本orderの最上位指針)

宙の辻の出発点は「**確実に槍ヶ岳の山頂に満月が重なる日時と場所を求めたい**」である。この原点に立ち返り、本orderは「**確実なものを提供する**」を全設計の最上位原則とする。

「確実」の定義:

1. **天体 = 決定論**。Astronomy Engineで正確に計算できる事実(位置・視高度・月齢・出没)は、未来であっても確実である
2. **気象 = 公表値の忠実な表示と機械的加工**。気象庁モデル(MSM/GSM)の計算値を、出典と初期時刻を明示してそのまま見せる・機械的に指数化する。**自らの予想は発表しない**
3. **統計 = 過去の事実の集計**。サンプル数と信頼区間を常に併記する
4. **判断は人**。アプリは判断材料を最良の形で並べ、読み取りと決断はユーザーに委ねる

この原則の帰結として、**予報業務許可(気象業務法)の論点は構造的に消滅**し、権利関係はOpen-Meteo(CC BY 4.0)+出典表記のみに単純化される。理念がそのまま法的安全設計になっている。

旧メッシュunkAIの機能的な代替は「**宙断面+観測点標高線**」である。雲頂とあなたの立つ高さの比べっこを、予測ではなく表示によって可能にする。予測せず、見せる。

## 1. 三製品の定義

### ① 宙断面

任意地点の「空の鉛直断面 × 時間」ビュー。封鎖中の既存実装を再生し、データを差し替える。

- **入力**: Open-Meteo気圧面16層(1000〜100hPa)の雲量・気温・相対湿度・ジオポテンシャル高度+地上主要系列。`models=jma_msm`(MSM予報範囲の先はGSM系で延長可)
- **時間軸**: 過去(Historical Forecast APIの準解析値)から未来(最新ランの予報値、MSM約4日)まで**1本のリボン**として連続描画
- **縦軸**: 気圧面。ジオポテンシャル高度による実高度目盛を併記
- **観測点標高線**: 地点標高(GSI標高タイル、既存デコーダ流用)を水平線で重畳。「雲頂が自分より下にあるか」を目視で読み取れるようにする(§0の機能的代替)
- **ラグアンサンブル表示**: 直近Nラン(既定3)を薄く重ね描き。ラン間で絵が揺れる領域=**公表予測の不確かさ**として見せる(自前の確率は作らない)
- **平年レイヤ**: 宙統計の地点統計を背景に重畳(P3で連携)
- **必須注記**: 気圧面雲量が相対湿度由来の診断値であること/出典(気象庁MSM・GSM、Open-Meteo経由、CC BY 4.0)/表示中データの初期時刻

### ② 宙検索(拡張)【Q1】

既存の宙検索に、鉛直プロファイル評価(旧称・宙メッシュ検索の仕様)を統合する。

- **評価軸(35軸・17系統)**: 16層 ×(雲量の望み方+重み)の32軸 + 天体系統(対象天体〈天の川/月/太陽等から1つ〉・視高度の好み・重み)の3軸
- 層別の「望み方」は3モード: **多いほど良い/少ないほど良い/目標値に近いほど良い** + 重み
- **UIは二段構え**: プリセット(「雲海」「月光サンドイッチ」〈下層厚い雲・中層クリア・上層天井・月低空〉「快晴の星空」「滝雲」)+詳細エディタ。プリセットはユーザー保存可(既存のGoogle Drive同期資産と親和)
- **マーカー**: 地図表示領域内で局所最大値(最小距離制約つきピーク検出)の上位N地点+スコアを表示
- **評価対象時刻**: 予報期間内の指定時刻、または指定時間帯内の最大スコア
- **データ取得**: 表示領域内の格子点をオンデマンド取得。IndexedDBキャッシュ(宙検索の既存パターン)。**v1は完全クライアントサイドを維持**(全国プリセットタイルの夜間バッチ生成はv2の任意項目)

### ③ 宙統計

気象の気候値(平年傾向)を提供し、月〜年スケールの計画(山行・遠征・定年後の平日行)を支える。

- **統計設計**:
  - 日付は**±7日の移動窓**(可変)で合算し、n≈100超を確保(日付単独はn≈8で薄い)
  - **平均場は持たない・使わない**。分位(中央値・四分位)と確率(例: P(下層雲量<25%))で保持
  - 宙検索連携は**「サンプルごとに採点 → スコアを集計」**(score→aggregate)。評価関数は非線形のため、平均場を採点する順序では「月光サンドイッチ」等の複合条件が発火しない。E[score(天気)] ≠ score(E[天気])
  - **天体は統計しない**: 対象年の決定論計算とのハイブリッド(例: 「2027-11-03: 晴れ確率◯%(過去統計)× 当夜は新月(計算値)」)
  - **特異日の扱い**: n・信頼区間を併記し、366日付の多重比較で偶然「特異」に見える日が生じる旨を注記
- **データ源**: **Open-Meteo Historical Forecast API(`models=jma_msm`、2018年〜、約8年)を正とする**。理由: 純CC BYで権利整理が「確実」であり、追加の枠組みに依存しないため(§0原則)。20年級の長期統計(京大RISH由来)は将来オプションとして封印し、採用検討時は旧orderの追記2(権利・運用)を再読すること
- **実装は二層+凍結一層**:
  - **地点層(v1の核)**: 任意地点のオンデマンド計算。1地点8年分の必要系列を分割取得(レート配慮)→統計化→**IndexedDBに永続キャッシュ**(2回目以降ゼロコスト)。宙断面の平年レイヤを兼ねる
  - **名所層(v1.5)**: 厳選地点リスト【Q2】を数週間かけて礼儀よくバックフィルし、静的JSONとしてリポ同梱・配信
  - 全国メッシュタイル: **v2以遠に凍結**(データ源判断とセット)
- **表示**: 日付スライダー/カレンダー+「この日の晴れやすさ」。宙検索プリセットの通年スコアカーブ(「月光サンドイッチが出やすい季節」グラフ)

## 2. データ仕様(共通)

- **予報**: `https://api.open-meteo.com/v1/forecast?models=jma_msm&...`
- **過去**: `https://historical-forecast-api.open-meteo.com/v1/forecast?models=jma_msm&...`(2018年〜)
- **主要変数**: 気圧面16層(1000/975/950/925/900/850/800/700/600/500/400/300/250/200/150/100 hPa)の `cloud_cover_*, temperature_*, relative_humidity_*, geopotential_height_*` + 地上 `temperature_2m, dew_point_2m, cloud_cover(全/低/中/高), wind_speed_10m, precipitation` 等
- **必須パラメータ**: `elevation=nan`(標高ダウンスケーリング無効化=モデル格子の生値)。`timezone=Asia/Tokyo`
- **レートと礼儀**: 非商用枠約1万コール/日。**課金換算は「地点×変数×期間」の重み付き**(HTTPリクエストにまとめても割引にならない)。日付・地点単位のキャッシュ必須、指数バックオフ、分割取得
- **表記義務**: Open-Meteo(CC BY 4.0)/気象庁(MSM・GSMの計算値である旨と初期時刻)/国土地理院(標高タイル出典)
- **地形**: GSI標高タイル(既存デコーダ流用)。用途は地点標高の取得と表示のみ(重い地形パイプラインは本orderには存在しない)

## 3. 実装フェーズと完了条件

| Phase | 内容 | 完了条件 |
|-------|------|----------|
| **P1 宙断面の再生** | 封鎖解除 → Open-Meteoデータ差し替え → 未来リボン → 観測点標高線 → ラグアンサンブル → 注記 | 任意地点で「過去24h〜未来約4日」の断面が描け、標高線・初期時刻・出典が表示される |
| **P2 宙検索の拡張** | 35軸評価エンジン+プリセット3種以上+マーカー | 「月光サンドイッチ」プリセットが表示領域内にマーカーとスコアを打てる |
| **P3 宙統計(地点層)** | オンデマンド統計+IndexedDBキャッシュ+宙断面の平年レイヤ | 任意地点で「11月3日±7日の晴れ確率」がn・信頼区間付きで表示される |
| **P4 名所層(任意)** | 地点リスト【Q2】のバックフィル(スロットル・中断再開可能)→静的JSON | リスト全地点の統計JSONが配信され、地図から即表示できる |

- 実装順の思想: P1は**ML不要・既存実装の再生**で最短距離。P1/P2/P3は独立性が高く並行可能。精度・見た目の磨き込みは各Phaseの完了条件達成後に回す
- 各Phase完了時に `docs/HANDOFF.md` を更新(既存プラクティス通り)

## 5. ライセンス・法規制の総括

- 全製品 = **Open-Meteo(CC BY 4.0・非商用枠)+ 気象庁出典明示 + 国土地理院出典明示**のみで完結
- **独自の予想を発表しない構成のため、予報業務許可(気象業務法)の論点は生じない**(§0)
- CEReS・RISH・ライブカメラは不使用(v1)
