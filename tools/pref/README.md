# tools/pref — 都道府県の輪郭データを作る道具

`data/pref/v1/pref-borders.json`(都道府県の外形+県境、約1.3 MB)を作り、確かめるためのスクリプトです。
データの中身・フォーマット・出典は `data/pref/v1/README.md` を参照。

## make-pref-borders.py — 生成
依存: Python 3 標準ライブラリのみ + `curl`。

```
python3 -I tools/pref/make-pref-borders.py [--work DIR] [--tol 500] [--min-ring-m 50] [--max-mb 3] [--prefs 01,02,...] [--keep-dl] [--out PATH]
```
| 引数 | 既定 | 意味 |
|---|---|---|
| `--work DIR` | `$TMPDIR/pref-borders` | 作業ディレクトリ。`dl/` にzipを1県ずつ落として使い終えたら消す。`edges/` に県ごとの輪郭辺(16バイト/辺)をキャッシュ。`run.log` に進捗 |
| `--tol` | 500 | 海岸線のDouglas-Peucker許容(m)。県境は間引かない |
| `--min-ring-m` | 50 | 海岸線だけの小さなリング(岩礁など)で、外接矩形の長辺がこれ未満のものは落とす。0で落とさない |
| `--max-mb` | 3 | 出力がこれを超えたら `--tol` を2倍(500→1000 m)にして書き直す |
| `--prefs` | 01..47 | 対象の都道府県コード(カンマ区切り)。少数の県で試す時に |
| `--keep-dl` | | zipを消さない |
| `--out` | `data/pref/v1/pref-borders.json` | 出力先 |

流れ: (1) 県ごとにGeoJSONを読み、偶奇で市区町村境を消して輪郭辺を得る → `edges/NN.bin`
(2) 県どうしの輪郭辺の共通部分=県境 (3) 辺を鎖にしてリング→アーク(県境は共有、海岸線は間引き。
間引いた弦が他県の陸を横切ったり囲んだりしないよう、近くの他県の頂点を格子に入れておき、弦と元の海岸線で囲む領域に他県の頂点が入る弦は最遠点で分け直す=位相の保護)
(4) 1e-5度に量子化し、polyline か整数配列の小さい方で書く。
安全弁: ダウンロードは https 限定・`--max-filesize 1500M`・900秒まで。zipの中のGeoJSONは 2 GB まで。
所要: 全国で約6分(ダウンロード約2.5分+処理)。メモリは北海道の処理時がピーク(数GB)。ディスクは < 1 GB。
`edges/` が残っていれば2回目以降はダウンロードなしで約110秒(`--tol` や `--min-ring-m` を変えて試せる)。
終了時に `result-<tol>-<min_ring>.json`(サイズと集計)を作業ディレクトリに書き、標準出力にも同じJSONを出す。

## verify-pref-borders.js — 指差し確認
依存: Node 22 標準ライブラリのみ。

```
node tools/pref/verify-pref-borders.js [--data data/pref/v1/pref-borders.json] [--mountains data/mountains.json] [--points 50000] [--seed 1] [--probe "lat,lon;lat,lon"] [--json]
```
1. アークを復号してリングを組み、点の内外判定(県の全リングに対する偶奇規則)と、どの県にも入らない点のための
   「最寄り県」(アークの外接矩形で作ったR木で最寄りの辺を探す)を実装する。
2. `data/mountains.json` の全山岳を分類し、`prefCode` に含まれていれば正解。
   正解率、最寄り県フォールバックに回った数とその最悪距離、不正解の上位10件(期待県の境界までの距離順)を出す。
3. 日本のbbox(経度122.9–154.0、緯度20.4–45.6)内の乱数点 N 個を分類して所要msを測る(ほとんどが海上の点で、最寄り県の探索が走る)。複数の県に入った点の数(重なり)も数える。
4. 県どうしの重なり: ある県だけが持つ海岸線アークの頂点が別の県の多角形の 10 m より深くに入っていないか(期待 0)。
   海岸線どうしは本来交わらないので、弦が他県の陸を横切る/囲むなら必ず相手の頂点が入る=頂点の検査で足りる。10 m 以内は N03 の県境の「縫い目」(幅ゼロの頂点のずれ)として別に数える。
5. `--probe` で任意の点(緯度,経度 を `;` で並べる)の県を出す。

`--json` を付けると結果のJSONだけを出す。

参照実装として、復号(`decodePolyline5` / `decodeDelta`)、内外判定(`inPref`。リングの辺を緯度の帯に分けて1点あたり数十辺だけ見る)、最寄りアーク(`buildTree` / `nearestArc`)、分類(`makeClassifier`。複数の県に入ったら自分の縁が最も近い県)はそのままアプリ側に写せます(`require` もできます)。

## 結果(2026-10-06、N03 2026-01-01版)
- 出力 1,323,718 バイト(許容500 m、小リング50 m未満を111,509個除外、位相の保護で分け直した弦61本)。アーク 11,979本、リング 11,727本、点 364,165個
- 山岳 1,063山中 1,062山が一致(99.9%)。外れた1山は鼻曲山(群馬/長野の県境から 1 m)。フォールバック 0件・重なりによる曖昧 0件
- 県どうしの重なり: 0(海岸線アークの頂点68,257個のうち、他県の 10 m より深くに入るもの無し)。N03の県境の縫い目は156頂点(幅は最大6.4 m)
- 乱数点 50,000個の分類: 約1.3秒(うち47,521点が最寄り県の探索)。内外判定だけなら約0.12秒
- 位相の保護を入れる前は、因島(広島)の4,496 mの弦が生名島側(愛媛)の小島2つを飲み、その上の点が広島県になっていた(差分のレビューで検出)。今は3点とも愛媛県
- 参考: 小リングを落とさない場合は許容500 mで 4,637,227 バイト、1,000 mで 4,606,540 バイト(岩礁のリングが大半を占めるため許容を上げても縮まない)
