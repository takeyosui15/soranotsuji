# legends/ — 普遍の学び(どのプロジェクトでも真)

1ファイル=1学び。プロジェクト文脈を脱がせて「どこでも真」になった学びだけを置く
(文脈つきの生の記録はprojects/へ。賞味期限が違うものを混ぜない)。

## 書式

先頭にOKF互換のYAMLフロントマター、本文は「状況 -> 誤り -> 正解 -> なぜ -> 出典」。

```markdown
---
type: legend
title: 検査ツールは壊した版で検出力を自己証明する
description: 新しい検査を作ったら、わざと壊した対象でFAILすることを先に確認する
tags: [testing, tooling]
timestamp: 2026-07-22
source: soranotsuji 第39ラウンド
---

## 状況
(どんな場面で)

## 誤り
(何をやりがちか)

## 正解
(何をすべきか)

## なぜ
(理由・原理)

## 出典
(プロジェクト・ラウンド・関連ファイル)
```

- 昇格(ここへの追加)は蒸留=編集判断で行う(プロジェクトの節目毎)。
- 改版は追記+出典で。降格はフロントマターに`status: archived`(ファイルは動かさない)。
- まだ空。蒸留第1陣は手順8(宙の辻のreviews/約70枚から選ぶ)。
