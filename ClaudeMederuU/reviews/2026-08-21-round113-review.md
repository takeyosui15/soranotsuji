## 実施内容

1. **w3m** — 未インストールだったのでaptで導入(0.5.3)。恒久化は環境のSetup scriptに
   `apt-get update && apt-get install -y w3m || true` を1行(依頼者作業)と案内。
2. **Google検索の実測** — google.com/searchへは200で届くが、curl/w3mにはJS前提ページが
   返り結果が取り出せない(基本HTML版gbv=1も空・DuckDuckGo HTML版はIPで接続リセット)。
   実現手段の三段構えを回答: ①WebSearchツール(動作確認済み・米国インデックス寄り)
   ②目的サイト直読み(curl+パース/w3m) ③本物のGoogleはProgrammable Search JSON API
   (無料100クエリ/日・キーは環境変数へ)。
3. **写真を見た** — note記事の画像はassets.st-note.comからDL→Readツールで視覚として見られる
   ことを実証。1枚目=28mm実写(夜明けの青・大天井岳山頂の花崗岩・雲に呑まれた槍の壁)。
   2枚目=**宙の窓のシミュレーション画像だと視認で発見**(白い地形モデルの穂先に満月・黄の軌跡線・
   目的点十字・「© 2026 宙の辻 - Sora no Tsuji」のフッター)。作ったアプリの計画図が実戦記事に
   「撮りたかった絵」として載っていた。

## 学び(次の私へ)

- **「見る」は読むの上位互換の瞬間がある** — テキスト抽出では2枚目は「焦点距離600mm」と
  しか分からなかった。画像を実際に見て初めて「これは写真ではなく宙の窓だ」と分かった。
  画像つき記事はDL+Readまでやると、文章だけでは落ちる決定的な情報(今回: 自作アプリの
  出力だという事実)を拾える。note.comの画像は assets.st-note.com のURLをHTMLから拾えばよい。
- **「〜を許可したい」は「〜という体験を実現したい」と読む** — Googleの素のSERPは技術的に
  読めなかったが、依頼者の目的は「最新の情報で判断」。目的側に立てば三段構え(ツール検索・
  直読み・API)で今日から実現済みと答えられる。手段の不成立で止まらず、目的の成立で答える。
- **外部サービスの機械読みの渋さは正直に測って正直に書く** — Google(JSのみ)・DDG(IP遮断)の
  失敗も回答に書いた。できないことを言わずに置くと、次に同じ期待が生まれる。
- **道具の恒久化はSetup scriptが持ち場** — セッション内のapt installは次のコンテナで消え得る。
  環境キャッシュに焼くには環境設定のSetup scriptへ(第111で読んだ公式ドキュメントの知識が
  さっそく効いた)。
