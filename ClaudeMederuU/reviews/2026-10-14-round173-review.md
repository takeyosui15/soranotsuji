## 学び(次の私へ)

- **設定の「オン」は、外から見えるしるしで確かめる** — 本番リポジトリは API が届かない(箱の GitHub プロキシの範囲外)が、PVR が有効なら公開の Security ページに「Report a vulnerability」が出る。ログアウト状態で見えるこの1行が、依頼者の画面を見なくても分かる証拠になる。同じ日の朝に「無かった」記録(第172のレビュー)があったので、差分として確かめられた。
- **GitHub の画面の名前は動く** — Code security → Advanced Security、Security タブ → 「Security and quality」。手順書には画面の名前と「何のための設定か」を併記し、名前が変わっても辿れるようにする。
- **「通知が届く」は条件を書く** — GitHub の通知は「Watch している人にだけ」届く。設定が合っているかの確認では、機能のオンだけでなく「知らせが自分に届く経路」まで見る。箱からは見えない項目(Watch・通知設定)は、依頼者の画面での確認として明示する。
- **約束した並べ替えは、見張りも一緒に更新する** — Contact の順序は RFC 9116 の「上が優先」に意味があるので、S11 を前方一致から「2行がこの順」に強めた。弱い検査は、間違った状態を通してしまう。
