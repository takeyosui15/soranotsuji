## 「記憶」の棚卸し — 何がどこにあり、Macへ移るか
-------------------------------------------------------------------------------

慎重になるべき「大切な記憶」の正体を、置き場所ごとに仕分けします。

| 記憶 | 置き場所 | Macで使えるか |
|---|---|---|
| CLAUDE.md / AGENTS.md(作法・セッション開始手順) | リポジトリ | ○ git cloneで移る。ローカルのClaude Codeも同じファイルを同じ規約で読む |
| docs/order.md + order-log/(往復の記録=引き継ぎ書) | リポジトリ | ○ 移る |
| docs/todo.md(付箋) | リポジトリ | ○ 移る |
| ClaudeMederuU/(デッサン・ナレッジ・レビュー・道具) | リポジトリ | ○ 移る |
| .claude/skills/kaiki(回帰の回し方) | リポジトリ | ○ 移る。ローカルでも同じ場所から読み込まれる |
| 会話のコンテキスト(セッションの短期記憶) | claude.aiの各セッション内 | ×(元々セッションを跨いで残らない。だからこそ上の仕組みを2人で作ってきた)。※写しを持ち込む道はある(下の「セッションの持ち運び」) |
| 検証ハーネス(apptest/vendor等) | クラウドの揮発領域 | ×(移らないが、kaikiスキルが再構築手順そのもの。ローカルでも同じ手順で作れる) |
| (Mac側で新たに増える)会話の記録 | Macの`~/.claude/projects/` | ローカル保存だが**既定30日で自動整理される**。つまりMacでも「長期記憶はリポジトリへ」の原則は同じ |

**要点: Claudeの長期記憶は、全部リポジトリの中にあります。**
リポジトリの正はGitHubなので、Macを増やしても・Macが壊れても、記憶は無傷です。
「セッションの短期記憶は毎回消える」前提で order.md の往復と kaiki スキルを設計してきたことが、
そのまま環境引っ越しへの備えになっていました(意図せざる一石二鳥です)。

## 記憶の区切りの判定基準(いつでも使える3条件)
-------------------------------------------------------------------------------

「今が区切りとして良いか」は、この3つで判定できます。

- [ ] **全部コミット/プッシュ済み**(GitHubに上がっていない作業が無い)
- [ ] **書きかけの実装が無い**(実装途中で中断しているものが無い。判断待ちはOK)
- [ ] **次の一歩が文書化されている**(order.md/todo.md/デッサンを読めば再開できる)

第45ラウンド終了時点の評価: **3条件とも成立**。
- 全作業はコミット507c3e6でプッシュ済み。
- koushi.js/anchor.jsは「完成+テスト全PASS」の状態で止まっている(書きかけではない)。
- 次の一歩(PAD指紋書式のご判断→PADレンダラ)はデッサン02/03とtodo.mdに文書化済み。

この3条件は将来も使えます。休暇明けに限らず、どのラウンドの終わりでも、
3つ揃っていればそこが「記憶の区切り」です。

## タイミングの選択肢比較
-------------------------------------------------------------------------------

| 選択肢 | 利点 | 難点 | 評価 |
|---|---|---|---|
| A. 休暇明けすぐ | 区切り成立済み。判断待ち状態=並行作業ゼロで一番安全。MederuU手順4を試運転にできる | 特になし | ◎ 推奨 |
| B. PAD書式確定+PADレンダラ完成後 | ③の実装がもう1歩進んでから | 待つ理由が無い(実装はどの環境からでも同じに進む)。区切りの成立度はAと同じ | ○ 可 |
| C. 宙の辻クローズ後 | 一番大きな節目 | 数ヶ月先。ローカルの利点(後述)をその間ずっと使えない | △ もったいない |

どの選択肢でも「記憶が失われる」ことはありません(上の棚卸しの通り)。
差が出るのは「ローカルの利点をいつから使い始めるか」だけです。

### ローカル(Mac)にすると増えるもの

- たけちゃんさんのMacの実ブラウザ(Safari/Chrome)での動作確認を、Claudeと同じ机でできる。
- コンテナ再起動でハーネスが消える問題が無くなる(ローカルは消えない)。
- iPhone実機をつないだ確認など、クラウドからは届かない検証に手が届く。
- 通信の往復が無い分、軽い作業の体感が速い。

### web版に残る利点(だから併用)

- スマホからでも依頼できる・Macの電源が入っていなくても動ける。
- 環境が毎回まっさら(変な状態が残らない)。
- 本セッションのような長い継続セッションの仕組み。

### セッションの持ち運び(知っておくと便利な2つ)

- **web→Mac**: Macのターミナルで `claude --teleport` とすると、web版のセッションを選んで
  **会話履歴の写しをローカルへ持ち込めます**(webのセッションはそのまま残る。写しなので、
  ローカルでの続きはwebには反映されない)。
- **Mac→スマホ**: ローカルで動かしているセッションは「Remote Control」でclaude.aiに繋ぎ、
  **iPhoneから進捗を見たり指示を出したり**できます(実行はMac側のまま)。
  山の上からMacの様子を見る、もできてしまいます。

## 以前のご質問(todo.mdのCONCERN)への回答
-------------------------------------------------------------------------------

todo.mdに書き留めてあった3つの疑問に、ここでお答えします。

### Q1. 「このフォルダへのアクセスは禁止とかできるのであろうか」

**できます。** Claude Codeは既定で「作業フォルダ(起動したフォルダ)の中」が守備範囲で、
その外を読み書きする時は許可を求めてきます。
さらに設定ファイルのpermissionsに拒否ルールを書けば、特定フォルダを恒久的に禁止できます。
書き場所は2つ: `~/.claude/settings.json`=Mac全体(自分専用)、`.claude/settings.json`=リポジトリ毎。
**個人のフォルダパスを含むルールはMac全体側へ**(リポジトリ側はGitHub経由でweb版とも共有されるため)。
例(個人書類を明示的に禁止する):

```json
{
  "permissions": {
    "deny": [
      "Read(//Users/あなたの名前/Documents/**)",
      "Read(//Users/あなたの名前/Pictures/**)"
    ]
  }
}
```

運用としては「`~/ClaudeRoot`の下だけで仕事をしてもらう」(起動場所のルール)が一番簡単で、
拒否ルールは心配なフォルダにだけ足せば十分です。

### Q2. 「インターネット検索は、全てできてしまうのであろうか」

**既定では検索・取得の道具(WebSearch/WebFetch)を使う時に許可を求めてきます**(勝手には検索しません)。
毎回聞かれるのが煩わしければ許可(allow)に、一切させたくなければ拒否(deny)に、
settings.jsonで恒久設定できます。例: `"deny": ["WebSearch", "WebFetch"]`(全面禁止。ツール名を裸で書くと全部にマッチ)。
特定サイトだけ許す中間もあります: `"allow": ["WebFetch(domain:github.com)"]`。
宙の辻の作業はローカル完結のテスト方針なので、普段はネット無しで困りません。

### Q3. 「デスクトップ版と連携?(トークンの消費量がわかりやすいように)」

CLI(ターミナル版)とデスクトップアプリはどちらも同じClaudeアカウントにログインして使い、
**サブスクリプションの使用量は、web版・CLI・デスクトップで共通のプールです**。
CLIの中では `/usage` コマンドで現在の使用状況(プランの残り)を確認できます。
つまり「web版で使った分+Macで使った分」が合算で見える形になります。
補足: デスクトップアプリには**Claude Codeが内蔵**されているので、ターミナルが苦手なら
デスクトップアプリだけで始める道もあります(CLAUDE.md・スキル・設定は両者で共通に読まれます)。

## iCloudの注意(慎重に、の本丸)
-------------------------------------------------------------------------------

`soranotsuji-dev-local`がiCloudフォルダ上にある件は、**唯一、事前に決めておきたい点**です。

- **Git公式のFAQが明文で警告しています**: 「クラウド同期サービスでリポジトリの一部でも同期しては
  ならない。オブジェクトの欠落・勝手な変更・参照の破損などの破壊を招く」(git-scm.com/docs/gitfaq)。
  iCloudはgitの構造を知らずファイル単位で同期するため、更新の途中で同期すると壊れる、という理屈です。
- 実際の事故の型も報告されています: 同期競合で`.git`の中に「main 2」のような複製が生まれて
  `fatal: bad object`になる・`.git`フォルダ自体が「git 2」に化ける・ロックファイルが他デバイスへ
  同期されて操作不能になる、など。
- 「Macのストレージを最適化」がONだと、使っていないファイルの中身が雲側へ退避されます
  (最近のmacOSでは見かけは普通のファイルのまま中身だけ空になるので、目では気づけません)。
  **Claude Codeと退避ファイルの組み合わせで実データが失われた事故報告もあります**
  (退避ファイルのコピーが0バイトになり、元を消して喪失。Claude Code公式issue #32637)。
- 今まで無事だったのは、たけちゃんさんの使い方(文書編集が中心)が穏やかだったからで、
  Claude Codeが働くと読み書きの量が桁違いに増えるため、リスクも増えます。

**推奨: Claude Codeの作業用クローンは、iCloudの外に新しく作る。**

- 場所は、たけちゃんさんが以前todo.mdに書いていた案の通り `~/ClaudeRoot/soranotsuji-dev` が
  ぴったりです(ホームフォルダ直下はiCloud同期の対象外)。
  ※注意: 「デスクトップと書類」のiCloud同期をONにしていると、`~/Documents`(書類)と
  `~/Desktop`は見た目がローカルでもiCloud圏内です。ClaudeRootは必ずホーム直下に。
- 既存のiCloud上の`soranotsuji-dev-local`は**そのまま残してOK**です(たけちゃんさんの書斎として)。
  2つのクローンがGitHub経由で同期するのは、gitの普通の使い方です(web版と今しているのと同じ)。
- 「記憶のバックアップはiCloudではなくGitHub」と役割を決めるだけで、慎重さの要件は満たせます。
  GitHubには全履歴が残っており、これが一番堅いバックアップです。

## 安全網(間違っても大丈夫、の確認)
-------------------------------------------------------------------------------

- ローカルのクローンは「GitHubの写し」なので、**丸ごと削除しても記憶は無傷**です。
- Claude Code本体のアンインストールも、リポジトリや記憶には影響しません。
- 最悪ケース(Macで何か壊した)でも、web版から`git push`済みの時点へ戻れます。
- 逆に一番避けたいのは「プッシュしていない作業をローカルに溜めること」— これは今の
  web版運用でも同じルールなので、新しく覚えることはありません。

判断はこの資料で、実施は `mac-migration-guide.md`(移行手順書)でどうぞ。
