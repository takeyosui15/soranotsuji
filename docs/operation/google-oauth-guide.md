# Google OAuth同意画面の公開設定ガイド(テスト→本番)

作成日: 2026-08-17(第104ラウンド)
更新日: 2026-08-17(第105ラウンド。本番公開の実施結果を反映)

> **実施済み(2026-08-17)**: v1.85.0リリース時に本番公開済み。ロゴも設定し、ブランド審査も
> 通過済み。テストユーザーでないアカウントでのログインも確認済み。
> 以下はその時の手順の記録+再設定・トラブル時の参照用。

## この手順書の目的

Googleドライブ連携(設定の端末間共有・Myセットのスプレッドシート同期)を、
開発者以外の一般ユーザーも使えるようにする「本番公開」への切り替え手順。
初期構築の経緯と手順は order-log を参照(本書末尾の「記録」)。

## 現在の構成(前提)

- OAuthクライアントは2つ。本番用(soranotsuji.net / www.soranotsuji.net)と
  開発用(127.0.0.1 / takeyosui15.github.io)。`script.js` 冒頭の `GOOGLE_CONFIG` が
  アクセス元ホスト名で自動切替する。
- スコープは `drive.file` のみ(非機密スコープ=このアプリが作ったファイルだけ読み書き)。
  **Googleの審査(検証)なしで本番公開できる設計**(2026-07-04の方式決定)。
- `privacy.html` / `terms.html` は作成済みで、同意画面のブランディングにリンク設定済み
  (2026-07-15。本番公開の前提条件はすでに揃っている)。
- 公開ステータスが「テスト」の間の制約:
  - **テストユーザーに登録したアカウントしかログインできない**。他の人がログインすると
    「エラー403: access_denied(このアプリはGoogleの審査プロセスを完了していません)」でブロックされる。
  - 付与した許可が**7日で失効**し、また同意画面からやり直しになる。
  - テストユーザーは最大100人。

## 本番公開の手順(所要2分・無料・アプリ側の変更は不要)

1. [Google Cloudコンソール](https://console.cloud.google.com/) → 上部でプロジェクト(soranotsuji)を選択。
2. 「APIとサービス」→「OAuth同意画面」を開く(新しいUIでは「Google Auth Platform」へ移動する)。
3. **「対象」(Audience)** のページを開く(旧UIでは同意画面ページ内の「公開ステータス」の欄)。
4. 公開ステータス「テスト」の横の **「アプリを公開」** ボタンを押す。
5. 確認ダイアログで「確認」。スコープが `drive.file` だけなので審査は求められず、
   **即時で「本番」になる**(もし「確認が必要です」と審査の案内が出たら、機密スコープが
   混ざっている。「データアクセス」のスコープ一覧を `drive.file` だけに絞ってからやり直す)。
6. 以上。クライアントIDの再発行・`script.js` の変更・再デプロイは不要。
   テストユーザーの登録は残っていても害はない(意味がなくなるだけ)。

## 公開後の確認

- [ ] テストユーザーでないGoogleアカウント(別のGmail)で `https://soranotsuji.net` を開き、
  ヘッダの🈚️→Googleログインが**ブロックされずに**できること。
- [ ] 同意画面にアプリ名と「プライバシーポリシー」「利用規約」のリンクが出ること。
- [ ] 既存のログイン(テスト時代に許可したアカウント)もそのまま使えること。以後は7日で切れない。

## 注意

- **ロゴは設定済み・ブランド審査も通過済み**(2026-08-17)。ロゴをアップロードするとブランド審査の
  対象になるが、本プロジェクトは公開作業時に設定して審査を通過した。以後、ロゴやブランド情報
  (アプリ名・リンク等)を変更すると再審査が走ることがある(変更しなければ何も起きない)。
- 「承認済みドメイン」への追加時にドメイン所有権の確認(Search Console)を求められたら、
  soranotsuji.net の所有者として画面の指示に従って確認する(初回のみ)。
- ユーザー数の上限: テスト=100人 / 本番(`drive.file` のみ)=上限なし。

## 困った時

| 症状 | 原因 | 対処 |
|---|---|---|
| エラー403: access_denied(審査プロセスを完了していません) | 公開ステータスが「テスト」のまま | 本手順で「アプリを公開」 |
| ログインの許可が毎週切れて同意画面が再表示される | テストモードの7日失効 | 本番公開で解消 |
| ログインポップアップが出ない/エラー400: origin_mismatch | クライアントIDの「承認済みのJavaScript生成元」に今のURL(ポート番号まで一致)が無い | 「認証情報」→該当クライアントの生成元にURLを追加 |
| 同意画面に「このアプリはGoogleで確認されていません」の警告 | 機密スコープの追加やブランド情報の変更で(再)審査対象になった | スコープを`drive.file`だけに戻す/ブランド変更なら審査完了を待つ(2026-08-17時点の構成は審査通過済み) |
