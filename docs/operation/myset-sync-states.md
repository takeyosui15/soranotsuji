# Myセットの状態遷移表 — 状態アイコン・ローカルストレージ・スプレッドシート

第67ラウンド(2026-08-09)。依頼者の叩き台(order-log/order-2026-08-09.md)をClaudeが再構成して埋めたもの。
VSCodeのKoushiプレビュー拡張(v0.2.0以降)でプレビューすると表として読める。

## この表の構え(叩き台からの再構成)

叩き台は「3つのセット × (アイコン+ローカルストレージ+シート)」を1枚に並べる形だったが、
次の3つの分解で、小さな表3枚+注記に組み直した。

1. **状態アイコンは独立した状態ではなく「導出値」** — アイコンはログイン・紐付け・同期判定から
   計算されるだけなので、遷移表ではなく導出表(表A)で1枚。アイコンを列に持つ必要がなくなる。
2. **本体の状態機械は「1セットとシートの同期関係」だけ(表B)** — セットが3つでも100個でも、
   全て同じ1枚の表に従う(セット毎の差は無い)。だから表は1セット分だけ書けばよい。
3. **「変更後登録前」系は別の小さな機械(表C)** — Myセットリストのフォーム⇄ローカルストレージの
   「登録」ライフサイクル(全て登録ボタン)は、シート同期とは独立した2状態の機械。混ぜない。

大事な設計原則: **表に書く状態は「アプリが観測できる状態」だけにする**。
アプリは「端末とシートに差があるか」を時刻(前回同期時刻とシートの更新時刻)でしか判定せず、
「どちらが新しいか」は追跡しない(保存か読込かはユーザーが決める設計)。
だから「端末が新しい/シートが新しい」を状態として書いても、突き合わせるコードが存在しない。

## 表B: 1セットとシートの同期状態遷移表(本体・ログイン済みの世界)

セルは遷移先の状態。「-」=何も起きない(案内のみ含む)。「※n」=表の下の注記。
罫線: 二重線の左=状態を変えるイベント群と、見た目が変わらないイベント群の区切り。

```koushi
- t:1.
  - r:1:h.
    - c:1:xr2. 現在の状態
    - c:2:xc4:bd. 更新・紐付けの操作
    - c:6:xc2:bd. 内容の変更
    - c:8:xr2:bd. 再確認(アイコン押下)
  - r:2:h.
    - c:2:bd. 保存
    - c:3. 読込
    - c:4. 追加(既存シート紐付け)
    - c:5. 解除
    - c:6:bd. 端末側を変更
    - c:7. シート側を変更
  - r:3:bs.
    - c:1. 未紐付け 😢
    - c:2:bd. -(一括更新はスキップ)※1
    - c:3. -
    - c:4. 差あり 👎(未同期で紐付く)
    - c:5. -
    - c:6:bd. -(対象外)
    - c:7. -
    - c:8:bd. 作成の確認→保存で 同期済み 👍
  - r:4.
    - c:1. 未確認 👎 ※2
    - c:2:bd. 同期済み 👍 ※3
    - c:3. 同期済み 👍
    - c:4. 差あり 👎(紐付け直し)
    - c:5. 未紐付け 😢
    - c:6:bd. 見た目変わらず ※4
    - c:7. 見た目変わらず ※5
    - c:8:bd. 同期済み 👍 / 差あり 👎 / 消失 😢
  - r:5.
    - c:1. 同期済み 👍
    - c:2:bd. 同期済み 👍(上書き)
    - c:3. 同期済み 👍
    - c:4. 差あり 👎(紐付け直し)
    - c:5. 未紐付け 😢
    - c:6:bd. 差あり 👎(即時)
    - c:7. 見た目変わらず ※5
    - c:8:bd. 同期済み 👍 / 差あり 👎 / 消失 😢
  - r:6.
    - c:1. 差あり 👎
    - c:2:bd. 同期済み 👍(端末→シート)※3
    - c:3. 同期済み 👍(シート→端末)
    - c:4. 差あり 👎(紐付け直し)
    - c:5. 未紐付け 😢
    - c:6:bd. 差あり 👎のまま
    - c:7. 差あり 👎のまま
    - c:8:bd. 👎のまま(端末側変更※6) / 同期済み 👍(差が無ければ) / 消失 😢
  - r:7:ba.
    - c:1. 消失 😢
    - c:2:bd. 再作成して保存→ 同期済み 👍
    - c:3. エラー ❌
    - c:4. 差あり 👎(別シートへ紐付け直し)
    - c:5. 未紐付け 😢
    - c:6:bd. -(対象外)
    - c:7. -
    - c:8:bd. 作成の確認→保存で 同期済み 👍
  - r:8:ba.
    - c:1. エラー ❌
    - c:2:bd. 成功で 同期済み 👍 / 失敗で ❌
    - c:3. 成功で 同期済み 👍 / 失敗で ❌
    - c:4. 差あり 👎(紐付け直し)
    - c:5. 未紐付け 😢
    - c:6:bd. 差あり 👎(同期済み経由時)
    - c:7. 見た目変わらず
    - c:8:bd. 同期済み 👍 / 差あり 👎 / 消失 😢
```

注記:
- ※1 一括の「更新」はシート未紐付け(😢)の行をスキップする(作成はユーザー判断=アイコン押下から)。
- ※2 「未確認」=紐付けはあるが、このセッションでまだ判定していない状態(再読み込み直後など)。
  表示は差ありと同じ👎(区別はない)。判定はセッション内メモリのため、再読み込みで全行ここへ戻る。
- ※3 保存のデータ消失ガード: 非表示・非オフライン・端末に内容なし・同期済み記録あり、の行は
  シートを空で上書きしないため保存を中止して差あり👎に戻す(「先に読込を」の案内)。
- ※4 端末側の変更で即👎になるのは「同期済み👍」の行だけ(それ以外は表示が既に👎のため変化なし)。
- ※5 シート側の変更はアプリからは即時に見えない(次の再確認・更新まで表示は変わらない)。
- ※6 **表を埋めて見つかった穴と修正(第67発見→第68修正・案a)**: 同期判定は時刻比較のため、
  当初は「端末側の変更」で付いた👎が再確認で👍に戻ってしまった(端末の内容の変更は時刻を動かさない)。
  第68ラウンドで「端末側に未保存の変更がある」印(localEdit)をセットに永続で持たせ、時刻が一致しても
  印がある間は👎のまま+「端末側に未保存の変更があります」の案内に修正。印は編集時に立ち、
  保存/読込の成功で消える。複製は元の印を引き継ぐ(端末コピー⇄シートコピーに同じ差が写る)。

表の外のイベント(状態を変えない/行を生むもの):
- 一括選択・切り替え表示・開く: 同期状態は変わらない(選択・表示・別窓を開くだけ)。
  ただし切り替えには内容管理の副作用がある(同期済み・非オフラインの非表示セットは端末の内容を持たない)。
- 行追加: 未紐付け😢の行が生まれる。
- 複製: シート紐付きの行を複製するとシートも複製され、同期済み👍で生まれる。
  紐付き無し(または未ログイン)なら未紐付け😢で生まれる。
- ログイン/ログアウト: 表全体の前提が変わる(未ログインは全行🈚️=表Aの順1)。

## 表C: Myセットリストのフォーム⇄ローカルストレージ(「全て登録」)

```koushi
- t:1.
  - r:1:h.
    - c:1. 状態
    - c:2:bd. フォームを編集(名称・行追加・行削除・並べ替え)
    - c:3. 全て登録
  - r:2.
    - c:1. 登録済み(ボタン通常)
    - c:2:bd. 未登録の変更あり(ボタン点灯)
    - c:3. -
  - r:3.
    - c:1. 未登録の変更あり(ボタン点灯)
    - c:2:bd. 未登録の変更あり のまま
    - c:3. 登録済み(ローカルストレージへ確定)
```

補足: この「登録」はシート同期(表B)とは独立。登録してもシートには何も送られない
(シートへ送るのは表Bの「保存」)。

## 特例と別系統

- **既定のセット(ID:0)**: 内容は常に端末保持(切り替えで内容を手放さない)。それ以外の遷移は表Bと同じ。
- **アプリ全体のGoogleドライブ同期(app.json)**: Myセットのシート同期とは別系統だが、
  似たアイコン(🈚️🕛😢👎👍❌)を使う。あちらは「ローカルストレージ全体⇄Driveのapp.json」の
  内容指紋ベースの判定(このドキュメントの対象外)。
