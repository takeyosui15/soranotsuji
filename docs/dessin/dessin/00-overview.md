# デッサン（dessin）
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------
## 共通仕様
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- 作っていただくClaudeさんに、迷わず、高品質なものを作っていただくための基準
- 私からは、分かりやすい仕様書を書くのが「愛」だと思う。
### 概要:
- Webアプリの設定は、ローカルストレージの唯一のキー「soranotsuji_app」以下にまとめる。
- Webアプリの状態を管理するための変数は、唯一のキー「appState」以下にまとめる。
  - SSOT(Single Source of Truth：信頼できる唯一の情報源)の実現
- Webアプリをテストするためにローカルストレージを削除(リセット)するためのページ(reset.html)を作成する。
- コーディング規約
  - 命名規則
    - グローバル定数:UPPER_SNAKE_CASE
    - グローバル変数:PascalCase
    - 定数:UPPER_SNAKE_CASE
    - 変数:camelCase
    - 関数名:camelCase
    - CSS:kebab-case
  - UIテキスト・コメントは**日本語**で記述
  - コミットメッセージも日本語（`feat:` / `fix:` / `style:` プレフィクス使用）
  - XSS対策として `escapeHtml()` を使用（ユーザー入力をDOMに挿入する際は必須）
  - **構造とスタイルの分離**: インラインスタイル（`style="..."`）は使用せず、CSSクラスで定義する。HTML/JSには構造のみ、`style.css`にスタイルを記述する。
- ラベル名やプレースホルダーの内容は、日本語が多いので、半角・全角に気をつける。
- 計算処理が重い場合は、クルクルやプログレスバー、進捗状況を伝え、なるべく内部で並行処理したり、キャッシュを作って再利用したりするように工夫する。

## URL仕様
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- 簡単にURLにクエリストリングを渡してアクセスすることで、簡単に目的の状態のアプリを開くことが出来るようにする。
### 概要:
- URLは2形式あり、どちらでも同じ状態を復元できる。
  - **長いURL**: キー名・キー値がそのまま並ぶ形式(`?date=20260722&time=203000&...`)。
  - **短いURL**: 全パラメータ文字列を可逆圧縮して`?query=`の1キーにまとめた形式。各URL取得の「短いURL」チェックボックス(初期値オン)で選ぶ。
- モードは3種類: `mode=preview`(プレビュー) / `mode=tsujisearch`(辻検索の自動実行) / `mode=tsujimesh`(辻メッシュ検索の自動実行)。
  - 第108ラウンドから、modeは「復元できるURLの印」と「(パネルキーを乗せない絞りURL用の)自動実行の指示」だけを担う。
    **キーの適用はmodeで絞らない**(URLに有るキーは常に適用=「発行は絞る、復元は絞らない」)。
    fullのURLではパネル状態キー(tsujisearch=true等)が自動実行の指示を兼ねる(開いた側で同じ検索を再計算して結果画面まで再現)。
- **URL由来の値はそのセッション限り**(第37ラウンドの決定): URLによって実際に変わった項目はローカルストレージへ保存しない(URL適用前の自分の値で凍結)。共有URLを開いても普段の保存状態は置き換わらない。

#### 短いURL(queryキー)の仕組み
- パラメータ文字列をLZW(共有シード辞書+可変コード幅9bit〜)で圧縮し、Base64URL(62文字+`-_`)で文字列化する。暗号化ではない(可逆圧縮のみ)。
- 出力の先頭に辞書の版数`~N~`を付ける(v1のみ無印)。デコード側は版数で辞書を選ぶため、**発行済みの古い短縮URLもそのまま読める**(v1〜v11の辞書は凍結保管)。
- **辞書の規則(v12〜・第40ラウンドで作り直し)**: シードは次の種類だけで構成する。
  1. **「&キー名=」**: 全URLキー(148個)。キーは必ず「&」と「=」に挟まれて現れるため、区切りごと登録する。
  2. **「キー値」**: 列挙可能な固定値(104個。true/false・天体ID・時刻モード・センサー種など)。値の前後の区切りは位置で変わるため、裸のまま登録する(「=値&」のような区切り付き値シードは意味が曖昧になるので置かない)。
  3. 定型3つ: `%2B0900`(タイムゾーン+0900) / `00%3A00`(時刻00:00) / `%23`(色値の先頭「#」)。
  4. **「&キー名=既定値」**(v13〜・第41ラウンド): キーと既定値のペア(127個)。既定値のままの
     項目が1コードで表せ、短縮URLが約半分になる。ペアは「v1.41.0時点の初期状態の実アプリが
     発行したURL」から導出して**凍結**(アプリの既定値が将来変わってもペア配列は変更しない=
     発行済みURLの保護。新しい既定値で作り直す時は新版を積む)。
- **仮想の先頭「&」**: 先頭キーだけは「&」が付かず「&キー名=」の辞書に乗らないため、エンコード時に仮想の「&」を1つ足してから圧縮し、デコード時に外す(v12以降。URL上には現れない)。
- キーを追加した時は、2配列(`_QP_KEYS_V12`/`_QP_VALUES_V12`)へ足した**新版**を作って版一覧へ積む(既存版は変更禁止=発行済みURLの復号用)。

#### URL取得ダイアログのオプション(2つのチェックは1段に横並び)
- 「:短いURL」(初期値オン): オン=圧縮した短いURL / オフ=キーがそのままの長いURL。
- 「:QRコード」(初期値オフ・第95ラウンド): オンにすると、URL文字列の代わりに**そのURLのQRコード画像(PNG)をクリップボードへコピー**する。
  - 生成はqrcode-generator(MIT・CDN)のローカル処理(通信なし)。誤り訂正はMで作り、URLが入り切らない長さならLへ落として再試行。それでも入らなければ「:短いURL」を案内する。
  - 画像コピーに未対応のブラウザではその旨を案内する(URL文字列コピーは従来どおり使える)。

#### 組込天体の色/線種(第89ラウンド叩き台→依頼者承認→**第91ラウンドで実装済み**=v17辞書とセット)
方針は第81ラウンドで承認済みの「天体毎キー・既定値のキーは省略」(My天体で数が増えるため、
1キーに詰める方式より天体毎キーの方が自然に伸び縮みする)。以下の設計どおりに実装した。

- キーの形: `bodyColor<天体ID>` / `bodyDash<天体ID>`(例: `bodyColorSun=%23FFD700`・`bodyDashMoon=1`)。
  - 対象は組込天体22個のみ。**My天体は従来のstarColor/starIsDashed(並び順対応)のまま**
    (既にURLで完全再現できているため変更しない)。
  - 値: 色は`#RRGGBB`(My天体のstarColorと同じ表記。URL上は%23)・線種は`1`=破線/`0`=実線(starIsDashedと同じ)。
- 既定値の省略: DEFAULT_BODIESの既定(色・線種)と同じ天体は**キー自体を発行しない**。
  - (第91〜107の省略設計)全て既定のままなら44キーが1つも付かず、URLの長さは今と変わらない。
  - **第108ラウンドで常時発行へ変更**: 既定値でも44キー全部を発行する。省略設計だと、開いた側が
    色を変えて保存していた場合に既定色URLで色が戻らない(共有URL再訪問題の一種)ため。
    既定値のままのURLは辞書v19の既定値ペアが1コード/キーに畳むので、変更したURLより短い
    (依頼者の採用条件・実測536字<592字)。
  - 表示/非表示に関わらず全天体を発行する(非表示天体の色も相手の画面で再現するため)。
- 復元: `bodyColor`/`bodyDash`接頭辞のキーを走査し、一致する組込天体のIDだけに適用(未知IDは無視)。
  復元後は表示天体メニューのUIへ同期。
- 短縮URL辞書(v17): 22天体×2属性=44個の「&キー名=」シードを新版に積む(当時は既定省略設計のため
  第3規則の既定値ペアは無し)。色値の`%23`は既存シードが受ける。既存版(v16以前)は凍結のまま。
- 短縮URL辞書(v19・第108ラウンド): 常時発行化に伴い「&キー名=既定値」44ペア(v1.85.0時点の
  DEFAULT_BODIESから凍結)+新規発行4キー(soraGrayscale/soraLabelScale/smBldg/smBldgTex)の
  名前シード+既定値ペアを追加。辻検索/辻メッシュ条件キーのシードはv12〜v15に収録済みのため追加なし
  (基準方位角tsujiAz等の値は位置依存でシード不適)。v18以前は復号のみ保証で凍結。
- リンター(verify124 L2)対応: 動的なキー合成(`'bodyColor' + b.id`)はemitKeysが静的に読めないため、
  発行側は44キー(または22ID)の**配列リテラル**からのforEachで書く(第80ラウンドの月間フィルタの前例)。
- 発行順: starId群の直後に、DEFAULT_BODIESの並び順で色→線種の順(辞書学習の安定のため順序を固定)。
- 「複数指定可」のキー(starId/starName/starRa/starDec/starColor/starIsDashed)はURLSearchParams.getAll()で取得し、starIdと対応する他のキーの内容が一致するようにする(My天体はstarIdの数字と同じ並び順で対応)。
- タイムゾーンは、URLを取得するときにそのブラウザが所属するタイムゾーンの情報を埋め込むことで、その作成されたURLを別のタイムゾーンの人が参照する時に、同じ日時情報の状態で参照できるようにするため。
- 数値・列挙値はURL復元後にnormalizeAppState()で既定の範囲・選択肢に丸める(壊れた値・範囲外の値は既定値へ)。
- 廃止キー: `tsujiMeshPixHeight`(項目廃止。旧URLでは無視される)。旧仕様にあった`startName`/`endName`(観測点名/目的点名)は実装していない(位置と天体定義だけで状態を復元する)。

### 目的:
- デバッグ作業や、何らかの問題があった場合にユーザーがローカルストレージをリセットできる様にする。
### 概要:
