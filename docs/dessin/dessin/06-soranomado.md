# デッサン（dessin）
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------
## 宙の窓メニュー
-------------------------------------------------------------------------------
-------------------------------------------------------------------------------


### 目的:
- カメラで写真と撮る時に、イメージしやすいように、観測点から目的点方向を画面内でシミュレーションをして、プレビューできるようにする。
### 概要:
- 機能概要
  - 宙の窓
    - 連なる山々や尾根筋の前景に、天の川や太陽や月などの天体が重なる景色をシミュレーションする。
    - 位置情報と日時情報から、天の川や太陽や月の天体の位置を算出し、国土地理院のDEM標高タイルを用いて、山々や尾根筋を描画する。
    - カメラから写真を撮るときに、例えば、センサーサイズは、フルサイズで、35mmのレンズで、絞りはF8で、ピントの合っている範囲は、フォーカスピーキングで赤色で表示する、山々や尾根筋を太陽光ヒルシェード＋標高グレースケールで立体的に表示する、といったカスタマイズができること。
    - 表示する天体は、表示天体メニューの辻ライン表示チェックボックスと連動する。
    - 月以外の天体は、視半径を考慮して、面積を持つ円で描画をし、月は、満ち欠けがるので、それをシミュレーションをする面積を持つ領域で表現するが、新月や新月に近いときは、どこに月があるかわからないので、月も、それ以外の天体も、中心座標を十字記号(+)で印をつける。また、月は、視半径の円を細い線で描画し、どれくらい満ち欠けがあるかわかるようにする。
    - プレビュー領域は、画面下部に表示する。高さは辻検索・最大化・コントロールメニューの開閉で動的に変わる(「プレビュー領域のサイズ変更動作」を参照)。

      - オンオフで地形を取得し直す(geomKeyに含まれる)。保存・共有URL(soraPhotoTex)・短縮辞書v20に対応。

### 仕様詳細:
- プレビュー領域:
  - 機能概要
    - 位置情報と日時情報から、天の川や太陽や月の天体の位置を算出し、国土地理院のDEM標高タイルを用いて、山々や尾根筋を描画する。
    - ダウンロードしたDEM標高タイルは、一時的にキャッシュして使い回す。
    - 視界範囲は、観測点からの距離0kmから、観測点と目的点(相手)の距離(km)を切り上げた数値の距離までを初期値とし、その奥行きを、レンズの焦点距離で指定する画角の範囲の扇形で、DEM標高タイルをダウンロードする。
    - 手前の山の輪郭や、手前に伸びる尾根筋が立体的に3Dで分かるように陰影をつけて描画する。陰影は、太陽の位置を光源とした陰影(太陽光ヒルシェード)と、視界範囲内の最高標高を白色とした標高グレースケールを組み合わせる(尾根の向きで明暗がつき、立体感が出る)。日時が夜間で太陽が地平線下のときも、太陽の方位を保ったまま光源の高度を底上げして、尾根のレリーフ(立体)を維持する。
    - DEM標高タイルの取得とPNGデコード・標高化は、ワーカープールで並列並行非同期処理する。取得に時間がかかる場合は、プレビュー上端に進捗バーを表示する(ワーカー/OffscreenCanvas非対応環境ではメインスレッドで逐次取得にフォールバックする)。
    - カメラから写真を撮るときに、例えば、センサーサイズは、フルサイズで、35mmのレンズで、絞りはF8で、ピントの合っている範囲は、フォーカスピーキングで赤色で表示する、山々や尾根筋を太陽光ヒルシェード＋標高グレースケールで立体的に表示する、といったカスタマイズができること。
    - 表示する天体は、表示天体メニューの辻ライン表示チェックボックスと連動する。
    - 月以外の天体は、視半径を考慮して、面積を持つ円で描画をし、月は、満ち欠けがるので、それをシミュレーションをする面積を持つ領域で表現するが、新月や新月に近いときは、どこに月があるかわからないので、月も、それ以外の天体も、中心座標を十字記号(+)で印をつける。また、月は、視半径の円を細い線で描画し、どれくらい満ち欠けがあるかわかるようにする。
    - 天の川は、どの位置に天の川があるか分かるように、天の川写真が背景になるように表示する。さらに、天の川の環(銀河赤道の大円)を白色の線で表示する。天の川の中心座標(銀河中心)は、他天体と同じ天体色の十字記号で表示し、その中心座標の軌跡(前後1日を含む計3本)も天体色の線で表示する。
    - 天の川や太陽や月などの表示天体の中心点の軌跡を、日時情報で指定される日付(前後1日を含む)の範囲で、天体色で細線で、プレビュー画面内に描画する。各日(前日・当日・翌日)の0:00〜23:59を1本ずつ、計3本の線で描く。
    - プレビュー領域は、画面下部に表示する。高さは辻検索・最大化・コントロールメニューの開閉で動的に変わる(「プレビュー領域のサイズ変更動作」を参照)。
    - 標高グラフと天体儀とは、トグルボタンで排他的に表示するが、辻検索の結果とは、同時に表示できるようにする。
    - 辻検索の結果の行を選択した場合は、日時情報が切り替わるので、それに合わせて、プレビューも描画される。
    - プレビュー画面の中心座標を十字記号(+)で印をつける。
    - 目的点(基準方位角・基準視高度=観測点から目的点を見た方向)に、赤い十字記号(+)の目的点マーカーを表示する。地形に隠れず常に見え、画面サイズに依らず一定の大きさで表示する。オフセットが0のときは画面中心の十字と重なる。
    - プレビュー画面は、マウスのドラッグ(スマホは2本指のスクロール)でパン(視線移動)できる。画面の内容が指に追従して動き、オフセット方位角・オフセット視高度がそれに連動して更新される(メニューの数値表示とも同期)。
    - プレビュー領域のサイズ変更動作(プレビュー領域内のプレビュー画面とコントロールメニューのサイズ変更を含む)
      - プレビュー領域が最大化されている場合。

          - コントロールメニューの開閉で、プレビュー画面のサイズが動的に変化する。
        - 辻検索ボタンが押下されていない場合。
          - ブラウザ内の上から縦3/3を宙の窓のプレビュー領域が占める。

        - 辻検索ボタンのオンオフで、動的にプレビュー領域とプレビュー画面とコントロールメニューのサイズ変更が動作する。
      - プレビュー領域が最大化されていない場合。

          - プレビュー領域のコントロールメニューが開いている場合。
            - プレビュー領域内の上から縦1/2をプレビュー画面が占めて、下から縦1/2をコントロールメニューが占める。

### 実測結果(第50ラウンド・許可ドメイン開通後):
- カタログAPI `api.plateauview.mlit.go.jp/datacatalog/plateau-datasets`: 9.1MBのJSONに全7,776
  データセット。建築物モデルは1,065件=**306都市**(「約300都市規模」を実測で裏取り)。

  LOD2tex=`data647.b3dm` 1.79MB(11,220頂点/13棟)。タイル単価は軽い。
- **全タイルがDraco圧縮必須**(glTFのextensionsRequiredにKHR_draco_mesh_compression)。
  「Draco遭遇時はスキップ」の当初案では1棟も出せない → **公式Dracoデコーダ(WASM)を採用**
  (Google製・Apache-2.0。three.jsのDRACOLoaderが使う物と同一)。配布元は**three同梱の

  threeの版とも組で固定される(gstatic直配はこの開発環境の許可リスト外だったのも決め手)。テストはvendor化。
  b3dm/glbの解釈(ヘッダ・JSON・RTC・ENU変換)は従来方針どおり最小自作。
- CESIUM_RTC(タイル毎の中心+相対float座標)。テクスチャは**WebP**(EXT_texture_webp)。
  batchTableに建物属性(gml:name=「東京都庁第一本庁舎」等・bldg:measuredHeight・用途・住所)が入っている(将来の楽しみ)。
- **(第98ラウンド追記)テクスチャの被覆はデータ側で建物毎に混在**: lod2系タイルセットは都市全域を
  覆うが、テクスチャ画像を持つのはLOD2テクスチャ整備範囲の建物のみ。b3dm実測(新宿区2025)では
  葉タイル510枚のサンプル9枚中テクスチャ画像入りは3枚で、都庁タイル(data647)ですら13棟が
  「テクスチャ付きプリム群+無しプリム群」の混在だった(札幌2020・横浜2024も同様の構造)。
  さらに148/448都市はLOD1のみ(テクスチャというデータ自体が無い)。アプリはマテリアル毎に正しく
  貼り分けており(無い建物=単色+陰影+夜は窓明かり)、無テクスチャのビルが混ざって見えるのは
  元データの整備状況によるもの(アプリ側の取りこぼしではない)。ヘルプにも同旨を記載(第98)。
- **高さ基準=真の楕円体高(WGS84)で確定**: 最低頂点71.31m = DEM標高34.6m+ジオイド高37.104m
  (GSIGEO2011・GSI APIで実測)。誤差0.4m。→ **標高 = 楕円体高 − ジオイド高N** の補正が必要。
- Nの供給: **EGM96のジオイド格子を同梱**(`data/geoid-jp.json`・0.25°格子・双一次補間・遅延読込。
  lp-japanと同じ同梱アセットの型)。東京でGSIGEO2011比Δ0.31m=建物の据え付けには十分。
- CORS: `assets.cms.plateau.reearth.io`(Google Cloud Storage)は`access-control-allow-origin: *`
  → ブラウザから直接fetch可。
- LOD1の高さは点群中央値ベース(都庁第一本庁舎: 実高243mに対し形状高211m。小物は一律3mも混在)。
  スカイラインの正確さはLOD2が上 — テクスチャOFF時もLOD2(無テクスチャ)優先の理由。

### 地図2.5D(段階4)の調査と設計案(第55ラウンド起草・GO待ち):

#### 調査結果(第55ラウンド実測):
- PLATEAUの建築物モデルに**MVT(ベクトルタイル)配信は無い**(現行カタログの建築物1,065件は
  すべて3D Tiles。MVTがあるのは土地利用・道路・都市計画等のみ)→「PLATEAU MVT」案は現行配信では成立しない。
- GSIベクトルタイル(最適化ベクトルタイル含む)の建築物レイヤに**高さ属性は無い**。
- GSI公式の「3D風地図」(gsivectortile-3d-like-building)は**種別による擬似高さ**で押し出す方式:
  普通建物=10m・堅ろう建物=40m・高層建物=100m(公式も「実際の高さではない。あくまで3D風」と明記)。

#### 設計案(2案・推奨は案A):
- **案A(第1版の推奨): GSI最適化ベクトルタイル+種別擬似高さ**
  - 出典: `cyberjapandata.gsi.go.jp/xyz/optimal_bvmap-v1/{z}/{x}/{y}.pbf`(XYZ配信あり=追加ライブラリ不要)。
  - MapLibreのfill-extrusionレイヤで押し出し。高さはGSI公式デモと同じ種別擬似(10/40/100m)。
  - 全国どこでも・軽量・依存追加ゼロ。地図の役割は「構図の当たり付け」(実寸・遮蔽の本丸は宙の窓)
    なので「風」で足りる、が推しの理由。ヘルプに「高さはイメージ」と明記する。
- **案B(将来の楽しみ): PLATEAU実高さの自前変換**
  - 3D Tiles→footprint+実高さのMVT/PMTilesを生成ツールで作り自前配信(Cloudflare R2等・転送無料)。
  - 実高さが得られるが、生成・配信・更新の運用が増える。案Aで物足りなくなったら。

### PoC実装の芯(第50ラウンド):
- 対象都市はまず静的表2件(新宿区・千代田区=実測済みURL+bbox)。範囲内に都市が無ければ何もしない(エラーにしない)。
- タイル選別: tileset.jsonの葉タイルのregionを扇(視界範囲・画角+余白)と突き合わせ、近い順に予算件数まで。
  → (第52ラウンド)奥行き上限を200kmへ(霞ヶ浦→ダイヤモンド富士+都心シルエット等の遠景)。
  都市単位の扇プレフィルタ(tileset取得前の足切り)+都市毎tilesetの並列取得+予算は見かけの高さ順。
- 座標変換: ECEF→測地(緯度経度・楕円体高)→標高=h−N→**地形格子と同じ厳密三角形解**
  (気差k・緯度別局所半径・E=d·sinA, N=d·cosA, z=d·tanAlt)で配置 → 遮蔽・実寸・気差が地形と自動整合。
- 無テクスチャ面: Dracoの法線を観測点ENUへ回し、太陽方向のランバートを頂点色に焼き込み(地形と同じ思想)。
- キャッシュ: b3dmのArrayBufferをLRU(タイルURLキー)・テクスチャ(ImageBitmap)もタイルURLキーで再利用。
  観測点や扇が変わったら幾何(ENU)だけ作り直す。
- 検証: 合成Dracoフィクスチャ(既知座標・既知高さの箱ビルをdraco3dでエンコード)で
  変換連鎖(ECEF→ENU→見かけ高さ)の数値を表明+UI連動+ON/OFF(verify128)。実ネットワークは使わない。
